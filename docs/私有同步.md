# LifeDiary 私有同步

当前公网 IP 使用单账号、长密码与 TOTP 验证器。账号只能通过服务器终端创建或重置。HTTPS 入口沿用 `https://129.211.50.155:8080`。同步服务绑定在 `127.0.0.1:8787`，由 HTTPS Nginx 转发。

浏览器登录后单独解锁资料库。随机资料库密钥分别由解锁口令派生密钥和随机恢复密钥包裹。口令使用 PBKDF2-SHA256，600,000 次迭代。记录和附件使用 XChaCha20-Poly1305，随机 nonce，认证记录标识、版本及附件引用。服务器看到加密记录、随机化附件名和同步元数据。应用使用内存中的解锁密钥，本机 IndexedDB 的日记正文、健康数值、图片和其他记录内容也按条加密。为了保留现有日历与排序查询，本机保留日期、时间等索引字段。网页版无法防止被篡改的网页脚本或已被控制的设备在解锁时读取内容。

记录离线先写本机。自动同步使用版本检查，服务器保留历次密文，冲突时保留本机版本和服务器版本供选择。附件按二进制独立保存，首次拉取会下载当前记录所需的附件。此版本的浏览器解锁后每 15 分钟无操作自动锁定。

## 本地验证

API 使用 Node.js 22.13 或以上版本的内置 SQLite，建议用当前已更新的 LTS。开发时另建一个目录并创建测试账号。

```bash
export LIFEDIARY_DATA_DIR="$(mktemp -d /tmp/lifediary-vault.XXXXXXXX)"
export LIFEDIARY_ORIGIN=http://127.0.0.1:5173
export LIFEDIARY_DEV=1
bash scripts/private-owner.sh init owner
npm run server
```

在第二个终端运行 `VITE_PRIVATE_SYNC=1 npm run dev`，用相同的地址登录。只有显式开发模式允许回环 HTTP。服务端测试用 `npm run test:server`，前端测试用 `npm test`，私有生产构建用 `npm run build:private`。

## 启用线上私有模式

1. 先从现有站点导出 JSON。备份包含明文，请离线妥善保管。私有模式使用另一个浏览器数据库，现有本地库不会自动上传或清除。
2. 将 `server/` 和管理脚本部署到 `/opt/lifediary`。创建无交互登录的 `lifediary` 系统用户，以该用户创建权限为 `0700` 的 `/var/lib/lifediary-vault`。用 Node.js 22.13+ 初始化账号，在服务器终端交互输入自己的长密码。验证器手工添加 TOTP 密钥。用密码管理器和验证器分别保管凭据。
3. 安装 `deploy/lifediary-vault.service`。如 Node 安装路径或站点地址不同，调整服务文件。确认服务启动且仅监听回环地址。将 `deploy/nginx-private.conf` 应用到 LifeDiary 的 `8080` HTTPS 站点，先备份现有配置，再执行 `nginx -t` 后重载。保留现有的证书续期服务和 `80` 端口验证路径。
4. 使用 `VITE_PRIVATE_SYNC=1 bash scripts/deploy.sh` 构建并发布。先用空资料库检查登录、首次解锁、跨浏览器同步、离线和备份恢复。保存恢复密钥后，在空资料库导入原来的 JSON。若多台设备各有不同旧记录，应先核对并整理为一份迁移备份。私有模式会拒绝用旧 JSON 覆盖已有记录的资料库。
5. 在第二台设备验证记录和图片已同步，并另做独立备份。需要移除旧明文缓存时，仅删除浏览器 IndexedDB 中的 `riji-db`，保留加密的 `riji-private-v1`。

生产账号初始化示例，需在服务器交互终端执行。

```bash
sudo -u lifediary env LIFEDIARY_DATA_DIR=/var/lib/lifediary-vault \
  bash /opt/lifediary/current/scripts/private-owner.sh init owner
```

## 恢复与日常维护

换手机时先将验证器迁移到新手机。验证器丢失时，通过服务器终端运行 `scripts/private-owner.sh reset owner`，重新设置账号密码和 TOTP。该命令撤销已有登录会话，资料库仍使用原解锁口令或恢复密钥。

以服务用户运行 `LIFEDIARY_DATA_DIR=/var/lib/lifediary-vault node server/backup.mjs /路径/全新的备份目录`。工具生成一致的 SQLite 快照、复制并验证快照引用的密文附件，并移除快照中的登录会话。将成功的备份复制到另一台机器或离线介质。单独保护并备份数据目录的 `auth.key`，它用于解密服务端 TOTP 密钥，和你的日记恢复密钥分别保存。

恢复演练应使用另一处测试目录和独立站点。复制快照的 `lifediary.sqlite`、`files/` 和单独备份的 `auth.key` 后启动服务，确认账号能登录，并用日记恢复密钥打开一条记录及其图片。若生产数据库回滚到较旧快照，先保全设备上的待同步记录再重新接入，避免把较旧快照当作最新数据。数据库和附件保存历史版本，需监控磁盘容量，按实际情况配置定期异地备份。

## 当前服务器部署

2026 年 11 月 6 日已在 `https://129.211.50.155:8080/` 启用私有版。

- 后台代码通过 `/opt/lifediary/current` 指向版本目录。
- 专用 Node 运行时位于 `/opt/lifediary/runtime/bin/node`。
- 数据目录为 `/var/lib/lifediary-vault`，由系统用户 `lifediary` 持有。
- `lifediary-vault.service` 已启用，API 只监听 `127.0.0.1:8787`。
- 前端由 `/var/www/lifediary/current` 指向私有版发布目录。
- `/opt/lifediary/finish-private.sh` 使用仓库内 `deploy/activate-private.sh` 的逻辑。后续操作需按该脚本的预检和备份流程执行。
- HTTPS 证书续期定时器继续运行，LifeDiary 的明文 HTTP 请求被拒绝。
- 异地定时备份尚未配置。应在确定独立备份位置后设置计划，并演练恢复。

检查服务时可以使用 `sudo systemctl status lifediary-vault.service`。排查错误使用 `sudo journalctl -u lifediary-vault.service`，避免记录账号密码、验证器密钥和日记解锁口令。

修改账号名可在服务器运行 `sudo /opt/lifediary/rename-account 新账号名`。名字支持 3 至 64 位英文字母、数字、点、下划线和短横线。修改后旧登录会话失效，使用新账号名、原密码与原验证器重新登录。账号名修改命令由 `deploy/rename-account.sh` 安装。
