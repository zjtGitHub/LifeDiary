# 股票备忘录功能设计

状态：首版已实现。本文中的股票示例为虚构示例，不接入行情数据。

入口与运行：顶部“股票备忘录”进入 `/stocks`，点击股票进入 `/stocks/:stockId`。使用 `npm run dev` 启动开发环境，`npm test` 运行测试，`npm run build` 进行类型检查和生产构建。生产部署需配置所有应用路由回退至 `index.html`，以支持详情地址直接访问与刷新。开发服务器和 Vite preview 已支持该回退。

## 1. 目标与核心场景

为每只股票建立一个长期记录空间，保存文字、图片、关键事件和当时的个人理解。回看时可以回答：某天我怎样理解它，依据是什么，之后又发生了哪些认识变化。

典型流程：添加股票 → 写下一条想法并附图 → 标记重要节点 → 之后持续追加 → 按时间回看。

第一版沿用项目的本地优先方式，数据保存在浏览器 IndexedDB，支持 JSON 备份。行情接入、交易执行、持仓盈亏、AI 分析与自动识别图片内容留待后续评估。

## 2. 入口与页面结构

顶部增加“日记 / 股票备忘录”主导航；现有月总结保持在日记模块内。股票备忘录使用独立工作区，适合长文和多张图片。

桌面端采用两栏：

- 左侧：股票列表，按名称或代码搜索，显示市场、记录数、最近记录时间；可切换关注中与已归档。
- 右侧：当前股票信息、新增记录入口、时间筛选、记录时间轴。

移动端先展示股票列表，点击进入单只股票页面，通过“返回股票列表”返回。筛选放在可展开区域，图片使用两列缩略图，点开查看大图。

首次使用显示“添加第一只股票”；股票没有记录时显示“写下第一次认识”。添加股票需要名称和市场，代码选填；市场提供自定义选项。填写代码时按市场规则规范化，以“市场 + 代码”检查重复；未填写代码时以“市场 + 名称”检查重复，同一市场下不同名称的无代码股票可分别保存。不同市场同名股票分别管理。

股票可改名、置顶或归档。归档保留所有记录且仍可搜索、恢复。第一版不提供股票及其全部历史的一键永久删除。

## 3. 一条记录包含什么

同一只股票同一天可以写多条，每条独立保存。

| 字段 | 规则 |
| --- | --- |
| 记录时间 | 默认当前时间，可精确到分钟，可补记过去；未来计划写在正文，不作为已发生记录 |
| 标题 | 选填，未填时从正文首行生成；仅有图片时使用“图片记录” |
| 正文 | 纯文本；正文与图片至少有一项 |
| 图片 | 多图上传、缩略图预览、查看原图、单张移除；可填写图片说明，例如“当时保存的公告截图” |
| 记录类型 | 想法、事件、操作、复盘；默认“想法” |
| 关键节点 | 独立开关，可与任何类型组合；用于筛选和时间轴突出显示 |
| 标签 | 自定义，例如“产品”“估值假设”“财报”“风险” |
| 当时态度 | 选填：偏乐观、中性、偏谨慎、未判断；随每条记录保存 |

记录“操作”只是个人文字备忘，不触发交易，也不用于自动计算持仓。记录类型和关键节点互相独立，例如“想法发生转变”同样可以是关键节点。

编辑区提供可选写作提示，不要求逐项填表：

- 当下的结论是什么？
- 支撑这个判断的事实有哪些？
- 哪些还是假设，什么情况会让我改变看法？
- 接下来需要验证什么？

## 4. 记录与回看的交互

### 新增记录

选择股票，点击“新增记录”，在当前工作区打开编辑区，股票自动关联。设置记录时间、填写想法、附图，按需标记关键节点。

输入过程中自动保存草稿，提示“草稿已保存”；点击“加入时间轴”发布。关闭编辑区、切换股票或刷新后可继续草稿。未发布草稿不出现在历史回看中。自动保存与发布失败均给出重试入口，不静默丢弃内容。

首次添加图片时进行格式、体积检查；图片解码成功后才入库。展示缩略图，按需读取原图，避免一次加载全部图片。编辑时移除图片，待发布成功后更新引用，历史版本所需图片继续保留。

### 时间轴

- 默认最新在前，按月份分组，月内按记录时间排序，同一时刻用创建时间稳定排序。
- 卡片展示日期与时分、标题、正文摘要、类型、态度、关键节点标记、图片数量。
- 展开后显示完整正文、图片和标签，可查看版本或追加复盘。
- 支持年份 / 月份筛选、关键节点筛选、当前股票内关键词搜索；组合条件显示匹配数，无结果时提示清除筛选。
- 年月选择器仅列出有记录的月份，并允许“全部时间”。切换股票后重置当前股票的筛选，防止新股票看起来没有记录。

### 回看某个时点

点击“回看某一天”，选择日期，显示当天及之前的记录，最近一条排在顶部，明确标注“截至 YYYY-MM-DD”。没有当天记录时显示最近一次记录的日期，不推断那就是用户当天的实际观点。

区分两种口径：

1. **按记录日期回看**：按用户填写的记录时间定位。后来补写或修改的记录也能看到，但注明“后补于…”或“修改于…”。
2. **只看当时已保存**：同时要求记录时间、首次发布时间不晚于所选日期结束；正文、标签、态度、关键节点和图片都取该时点之前最后一次发布的版本。后补记录不混入当时的信息。

日期结束按应用使用的本地时区计算，保存为带时区语义的时间戳；首次创建、发布时间和修改时间由系统生成，用户不能直接编辑。离线本地时间并非外部认证时间，页面避免使用“真实历史认证”等表述。

### 编辑与复盘

草稿可以自由编辑。已发布记录修改后创建新版本，旧版本的文字、图片、记录时间和其他字段一起保留；版本列表显示修改时间，可以展开查看。

“追加复盘”新建一条当前时间的记录，关联原记录，原文保留。复盘开头展示原记录日期和摘要，双方都能跳转，便于看到观点如何变化。

删除已发布记录采用移入回收站，可恢复；数据库保留历史与删除时间。在“只看当时已保存”模式下，按当时的删除状态展示，之后删除不会抹掉此前的回看。第一版不提供回收站永久清空。

## 5. 图片与关键节点如何呈现

关键节点卡片显示“关键节点”文本标记和明显的时间轴圆点，不只依赖颜色。关键节点开关可随时筛选，普通想法仍可从全部记录中查看。

图片缩略图显示图片说明与序号，点击打开大图并支持前后切换；手机支持左右滑动。历史版本查看其对应图片，后来的替换不会影响旧版本。

可选的下一阶段功能：勾选两条历史记录并排比较正文、态度、假设与图片；股价图上的记录标记需要接入行情后再设计。

## 6. 数据设计与现有项目衔接

保留现有日记、月总结和计划的数据结构，新增加独立表。已存在的数据库升级仅新增表，不改写日记。

| 实体 | 主要字段 |
| --- | --- |
| Stock | id、market、code（已规范化）、name、pinned、archivedAt、createdAt、updatedAt |
| StockNote | id、stockId、draft、currentRevisionId、firstPublishedAt、deletedAt、createdAt、updatedAt |
| StockNoteRevision | id、noteId、stockId、revisionNumber、occurredAt、title、text、type、isKeyNode、stance、tags、images（ID 与说明）、reviewOfNoteId、publishedAt、deleted 状态 |
| StockNoteImage | id、blob（含类型与大小）、thumbnail、name、createdAt |

说明：草稿独立保存在 StockNote 中；发布时在同一个事务内写入不可变版本、更新当前版本与首次发布时间。版本携带完整字段快照；图片文件不可变，通过 ID 跨版本复用。实现中每个版本保存 `{ id, caption }` 图片引用，修改说明只改变新版本的引用快照，不改写旧版本。删除与恢复也生成状态版本。后补记录的识别依据系统首次发布时间与用户记录时间之间的关系。

索引：有代码股票的唯一键 `[market+code]`，无代码时省略 code，不进入该索引；记录索引 stockId、`[stockId+updatedAt]`；版本索引 noteId、`[stockId+occurredAt]`、`[stockId+publishedAt]`、唯一键 `[noteId+revisionNumber]`。时点回看先选择符合条件的每条记录版本，再应用关键词和关键节点筛选。

可复用图片文件处理、标签规范化、保存状态样式、时间轴外观及备份转换逻辑。图片组件需要补充大图预览；数据不能直接复用以日期为唯一键的 dayEntries 表，否则无法表达同日多条和独立版本。

备份导出增加股票、草稿、版本与图片数据。导入前完整校验关联关系和图片引用，失败不覆盖现有数据；导入在事务中执行。恢复旧版备份仍按全量恢复规则处理，导入提示明确列出股票备忘录也会被覆盖，没有该模块的旧备份会将其清空。

时间轴按每批 30 条分批展示；列表查询不读取图片 Blob，展开详情再加载图片。当前查询范围为所选股票的记录元数据，历史时点模式额外查询该股票的历史文本版本。图片上传先验证格式、大小与解码，再生成最长边 420px 的缩略图，原图保留；单张最大 15 MB，每条最多 20 张。

导入备份使用应用内确认弹窗，明确说明覆盖范围；有打开的股票编辑器时，先关闭并保存草稿再导入。恢复过程中暂停日记自动保存，避免尚未完成的编辑覆盖恢复的数据。

## 7. 首版范围与验收

首版包括股票管理、同日多条记录、文字多图、关键节点、标签、时间轴、按日期回看、草稿恢复、版本保留、关联复盘、回收站恢复、完整备份与移动端适配。

验收场景：

1. 添加两只同名但不同市场的股票，记录互不混淆；相同市场代码重复添加时定位已有股票。
2. 同一天给一只股票写两条不同想法并附图，时间轴按时分显示，两条均能独立展开。
3. 标记关键节点后筛选只看节点；取消筛选能恢复全部记录。
4. 选定历史日期后能看到截至该日的记录；没有当天记录时说明最近记录日期。
5. 今天补记过去的想法，“按记录日期”中标明后补，“只看当时已保存”中排除。
6. 后来修改旧记录的文字、态度、日期、标签、关键标记或图片，历史时点仍还原当时版本。
7. 追加复盘形成新条目，原记录内容保留且双方可跳转。
8. 编辑中切换股票、刷新或上传失败不会丢失已保存草稿；发布失败可以重试。
9. 移入回收站后可恢复；历史时点正确反映当时是否已删除。
10. 数据库升级保留现有日记；新备份完整还原股票及图片，旧备份兼容，异常备份不破坏现有数据。

后续再考虑记录对照、周期复盘、日记关联、行情标记与导出单只股票研究档案。
